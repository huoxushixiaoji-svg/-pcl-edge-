# PCL 百宝箱下载助手 · Edge 实验版 0.1.2

用途：在 Edge 开始普通文件下载时，自动打开你本机的 PCL，进入“更多 → 百宝箱 → 下载自定义文件”，填写链接与文件名，沿用该页面的“保存到”目录，使用 PCL 的多线程引擎下载。

**这是非官方实验版，需要“Edge 扩展 + Windows 本机连接程序”两部分。当前交付环境无法运行 Windows / Edge / PCL，尚未完成 Windows 实机端到端测试；请先按下面的步骤检测，再用一个小型公开文件试下载。** 安装程序会在你的电脑上编译并运行连接程序的基础自检，扩展中的检测会检查实际 PCL 页面控件。

## 适配的 PCL 程序

- 适配时使用的 `Plain Craft Launcher 2.exe` 与样本压缩包 `PCL-2.13.1.1(1).zip` 中“最新正式版”目录的 EXE 字节完全相同。
- EXE 内部标识为 **正式版 2.13.0.1**，压缩包名 2.13.1.1 不等于其内置 EXE 的版本。
- SHA-256：`0ab0b28a93cc4d0754a9fa488b5939b5e092f0e5fb3f1e6550cc92a5d3f6577f`
- 已静态确认下载输入框、回车处理和任务日志格式；没有找到可直接把下载链接传给该 EXE 的命令行参数。
- 本安装包不包含 PCL 主程序。安装时选择你已保存到电脑上的那份 EXE。

## 已安装旧版：直接更新

1. 先关闭扩展的“自动接管”，等待正在交接的任务结束，再完整解压本修正版。
2. 双击 **`Update.cmd`**。它沿用已配置的 PCL EXE 路径，更新连接程序及扩展文件，无需重新选择主程序，也不删除浏览器内的设置与记录。
3. 在 `edge://extensions` 找到本扩展，点击**重新加载**（圆形箭头），确认版本显示 **0.1.2**。
4. 在 PCL 中打开“更多 → 百宝箱 → 下载自定义文件”，确认 **“保存到”** 是你要用的目录；需要修改时点旁边的“选择”。
5. 打开扩展弹窗，重新点击“检测百宝箱并启用接管”。应显示 **“跟随 PCL 百宝箱‘保存到’”** 和相同目录。

0.1.1 修复了旧版固定使用 `Downloads\PCLDownloads` 的问题。旧版 `config.json` 中的 `downloadFolder` 不再决定保存位置；每次任务都重新读取 PCL 当前值，且不会改写该输入框。如果旧版曾改变过百宝箱中的目录，请在 PCL 里重新选一次你期望的位置。

0.1.2 补上最终链接、文件大小与浏览器检查状态变化后的重新判断，并在网络响应信息晚于下载创建时重新检查。弹窗新增“最近 Edge 下载”：直接读取 Edge 的最终下载链接，提供复制按钮，并显示未自动接管的原因。对仍在进行中的公开直链，可以在确认后点击“尝试用 PCL 接管”；需要登录或表单内容的链接可能仍无法在 PCL 下载。

## 首次安装

1. 将本压缩包**全部解压**到普通文件夹。不要直接在压缩软件里双击脚本。
2. 先手动打开 PCL，完成首次提示。确认“更多 → 百宝箱 → 下载自定义文件”可见；PCL 和 Edge 都使用普通权限运行。
3. 双击 **`Install.cmd`**，在文件选择窗口里选中 `Plain Craft Launcher 2.exe`。不需要安装 Python、Node.js 或 AutoHotkey，也不需要管理员权限。
4. 安装完成后，在 Edge 地址栏输入 `edge://extensions`，打开**开发人员模式**，点击**加载解压缩的扩展**。
5. 选择 `%LOCALAPPDATA%\PclEdgeBridge\extension` 文件夹。可将这一行粘贴到文件选择窗口的地址栏后回车，或使用安装程序打开的目录。
6. 点击 Edge 工具栏的扩展按钮，打开 **PCL 百宝箱下载助手**，点击**检测百宝箱并启用接管**。检测会打开 PCL，不会创建下载任务。显示检测通过后才会自动开启接管。

固定扩展 ID：`onigneicjankgfnnepllcekbenagoolk`。不要删除 `manifest.json` 的 `key`。

**保存位置由 PCL 百宝箱的“保存到”输入框决定。** 请直接在 PCL 里选择需要的文件夹。插件在检测和每次开始任务时读取它；如果为空、不是完整路径或无法写入，会停止交接并提示处理，不会替换成另一个默认目录。中途发现目录被改变时也会停止本次交接。

安装脚本的 `ExecutionPolicy Bypass` 只用于这一次脚本进程，不永久修改系统执行策略。安装程序在当前用户下注册一个 Edge 本机通信入口；不会更改浏览器代理、系统下载关联或 PCL 程序。

## 日常使用

- 和平常一样在 Edge 点击下载。符合条件的任务会短暂暂停，PCL 会弹到前台并自动填写任务。
- 交接时请暂时不要操作 PCL 或切换窗口。自定义控件需要根据实时位置模拟点击，输入框使用 Windows UI Automation 填值。
- 连接程序会按回车触发 PCL 下载；**只有新写入的 PCL 日志确认建立了对应下载任务，扩展才取消 Edge 原任务**。已触发但未确认时，保留 Edge 暂停状态并显示处理按钮。
- 原 Edge 下载列表可能显示一条“已取消”的记录，这是成功交接后的预期行为。
- 在 PCL 的任务管理中查看实际进度、下载完成或失败。扩展显示“已建立任务”不等于文件已下载完成。
- 多个任务按顺序填入 PCL；PCL 如何并发下载由它自身控制。同名文件或同名交接会自动加 `(1)`、`(2)` 等后缀。
- 也可右键一个文件直链，选择“使用 PCL 下载此直链”。手动发送只发送 URL，不携带登录信息；不要对普通网页入口使用此功能。
- 扩展弹窗中可临时关闭接管，设置文件大小门槛或排除网站。任务记录保留在浏览器本地，最多保留 30 条已结束记录；待处理异常记录保留到你处理为止。
- 没有弹出 PCL 时，请打开“最近 Edge 下载”，点击“刷新下载记录”，查看原因和“最终下载链接”。已获取链接但未观察到对应请求、包含 Cookie、接管未启用等情况会分别说明。下载已完成时只复制链接，不再自动创建重复任务。

## 哪些下载仍由 Edge 处理

自动模式只接管观察到的、无 Cookie/Authorization 的 HTTP/HTTPS GET 请求。以下情况会跳过：

- 需要登录、Cookie、Authorization 或 POST 表单提交的请求；
- `blob:`、`data:`、本地文件、网页生成的导出文件；
- 未观察到完整请求信息、请求结果异常、已经完成或无法暂停的下载；
- Edge 已标记为可疑的任务，其他扩展发起的下载，以及无痕窗口下载；
- 设置中排除的网站、未达到大小门槛的文件。

某些公开网站也会发送普通 Cookie，这些下载会保守地留在 Edge。右键手动发送只适合你确认无需登录的文件直链。

PCL 不会继承 Edge 的 Cookie、请求正文、Referer、客户端证书或浏览器代理配置；部分防盗链或临时链接仍可能失败。服务器必须允许分段下载才有机会多线程提速，实际速度取决于服务器和网络，不能保证一定更快。

## 出现问题

| 现象 | 处理方式 |
| --- | --- |
| 提示找不到本机连接程序 | 重新运行 Install.cmd；检查扩展 ID；关闭再打开 Edge。单位管理的浏览器可能限制本机通信。 |
| PCL 已更新、移动或换了 EXE | 重新运行 Install.cmd 选择新位置，再检测百宝箱。 |
| 检测显示的保存目录不符合预期 | 在 PCL 百宝箱的“保存到”重新选择目录，再检测。确认扩展是 0.1.2，且已运行该版本的 Update.cmd。 |
| Edge 下载正常，但 PCL 没打开 | 打开扩展的“最近 Edge 下载”，刷新并查看原因；确认接管已开启。若提示未观察到对应请求，可先复制最终链接，或确认公开直链后手动接管。 |
| 提示携带 Cookie 或登录信息 | 最终链接已经获取，但不会自动交接该请求。登录网站或网盘可能需要 Edge 中的会话；公开文件的普通 Cookie 也会触发此提示。 |
| 提示保存目录为空或无效 | 在百宝箱点击“选择”，指定一个完整路径，例如 `D:\Downloads`，然后重新检测。 |
| 找不到“更多”或“百宝箱” | 取消 PCL 中对应页面的隐藏设置，回到主界面，关闭首次提示/弹窗。也可手动进入百宝箱并滚动到下载输入框后检测。 |
| PCL 未在前台/权限不匹配 | 不要以管理员身份启动 PCL；检测期间不切换窗口。需要时点击 PCL 主窗口后重试。 |
| 百宝箱地址栏已有内容 | 为避免覆盖你正在编辑的任务，交接会停止；先完成或清空地址栏。 |
| “无法确认”或本机连接超时 | 先看 PCL 任务列表。已建立对应任务就选“保留 PCL”；未建立或已经失败，则先在 PCL 取消该任务，再选“恢复 Edge”。 |
| 恢复 Edge 失败 | 打开 `edge://downloads` 手动继续；如果链接已过期，关闭接管后回原网页重新下载。 |
| PCL 接管后 403/下载失败 | 关闭接管，再回原网页用 Edge 重新下载。PCL 任务建立后的失败不会自动重建浏览器请求。 |
| 安装编译失败 | 需要 Windows 10/11 64 位、.NET Framework 4.8 和 Windows PowerShell 5.1。保留红色错误文本以便排查。 |

卸载：先在 Edge 关闭接管并处理完暂停任务，删除扩展，再双击 `Uninstall.cmd`。它移除本连接程序及本机通信注册项，保留 PCL 与已下载文件。

## 权限与实现

- `downloads`：暂停、恢复、取消对应浏览器下载并读取文件名。
- `nativeMessaging`：仅与本机 `com.local.pcl_download_bridge` 通信，允许来源限定为上述扩展 ID。
- `webRequest` 与 HTTP/HTTPS 站点权限：判断请求方式及是否携带登录凭据；不改写网页和请求。Cookie/Authorization 只检查是否存在，不保留或传递其值；请求元数据最多在扩展内存保留两分钟。
- `storage`：本地设置和任务状态。为了提供恢复入口，已接管任务的 URL、文件名与状态会保存在扩展的本地存储中；最近一次判断仅存下载编号、文件名与原因，不另存未接管链接或请求头。弹窗中的链接直接从 Edge 下载记录读取；卸载扩展会清除扩展本地存储。
- `notifications`、`contextMenus`：显示失败提醒与文件直链菜单。
- 本机程序只启动用户安装时选择的 EXE，传输内容是长度前缀 JSON；不把 URL 拼接进 shell 命令，不开本地 HTTP 端口。
- 没有读取浏览器密码、上传遥测或修改 PCL EXE。程序仅在本机操作 PCL 的下载表单，并读取本次操作之后追加的 `PCL\Log1.txt` 以确认接收。
- PCL UI 可能随版本改变，因此本方案的稳定性取决于实际控件与日志是否保留。它不是 PCL 官方提供的外部下载接口。

相关官方说明：[Edge Native Messaging](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/native-messaging)、[Chromium downloads API](https://developer.chrome.com/docs/extensions/reference/api/downloads)。

开发者可在安装包目录运行 `node --test tests/*.test.mjs` 检查扩展的关键交接逻辑。Windows 安装时自动运行 `Bridge.exe --self-test` 验证本机报文、文件名、URL 与日志确认的基础逻辑；这些不替代实际下载测试。

## 文件

`extension/` 是 Edge 扩展；`native/Bridge.cs` 是完整 C# 源码；`Install.*` / `Update.cmd` / `Uninstall.*` 是安装、更新、卸载入口；`tests/` 是回归测试；`VALIDATION.md` 记录交付前已验证的范围。
